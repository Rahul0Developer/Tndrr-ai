Executive Overview & System Architecture

This technical report delivers the complete engineering assessment for the Tndrr AI Internship Assignment. The project investigates three foundational pillars of modern applied language model engineering: parameter-efficient instruction tuning, grounded zero-framework document retrieval, and local quantized inference under strict compute budgets.

1. Assignment Scope & Task Objectives

Task 1: LoRA / QLoRA Tuning

Fine-tune Qwen2.5-0.5B-Instruct using PEFT LoRA to convert natural language commands into strict, deterministic JSON schemas across 6 functional intent classes with zero hallucinations.

Task 2: Zero-Framework RAG

Build an end-to-end RAG architecture on the 48-page NIST AI RMF 1.0 PDF without LangChain/LlamaIndex, evaluating 300w vs. 600w chunking granularities and Recall@5 on 15 verified questions.

Task 3: Local Quantization

Benchmark Q8_0 (8-bit) and Q4_K_M (4-bit) GGUF models via llama.cpp on host CPU across 10 prompts; profile memory bandwidth and derive theoretical serving math for 20 users on a 24GB GPU.

3. Model Selection & Theoretical Justification

Primary Model — Qwen2.5-0.5B-Instruct: Architecturally configured with 494M parameters, 24 transformer layers, hidden dimension $D=896$, and Grouped-Query Attention ($N_{\text{heads}}=14, N_{\text{kv\_heads}}=2$). This compact size achieves three critical operational objectives: (1) low training footprint ($\sim 1.18\text{M}$ LoRA parameters fitting in $<2.5\text{GB}$ VRAM), (2) sub-second generation on host CPU, and (3) tiny per-token KV cache footprint ($12\text{ KB/token}$).

Embedding Model — all-MiniLM-L6-v2: Generates 384-dimensional dense vectors with sentence-level mean pooling. Offers optimal balance between semantic precision and storage ($<0.1\text{MB}$ index matrix), avoiding out-of-memory overhead during matrix dot-product retrieval on 8GB host RAM.

Task 1: Parameter-Efficient Fine-Tuning (LoRA / QLoRA)

Small instruction-tuned language models frequently fail structured output tasks by introducing conversational preambles, dropping required schema keys, or hallucinating tool arguments. Task 1 enforces strict schema adherence via Low-Rank Adaptation.

1. Model Architecture & Fine-Tuning Setup

Target model: Qwen2.5-0.5B-Instruct (494M parameters). Low-Rank Adaptation was injected across all multi-head attention projections: $\mathbf{W} = \mathbf{W}_0 + \frac{\alpha}{r}(\mathbf{B}\mathbf{A})$ where $\mathbf{B} \in \mathbb{R}^{d \times r}, \mathbf{A} \in \mathbb{R}^{r \times k}$.

  • LoRA Hyperparameters: Rank $r=8$, Alpha $\alpha=16$ (scaling factor $=2.0$), Dropout $=0.05$, Target modules: q_proj, k_proj, v_proj, o_proj. Total trainable parameters: 1,179,648 (0.24% of model).
  • Training Execution: 3 epochs (225 global steps), batch size 4 (effective batch size 4), learning rate $2\times 10^{-4}$ with cosine decay, FP16 precision on NVIDIA T4 GPU. Prompt tokens were masked with $-100$ so cross-entropy loss was backpropagated exclusively on assistant JSON tokens.

2. Dataset Synthesis, Stratification & Verification

Generated synthetic natural language requests mapped to canonical schemas across six intents: set_reminder, create_event, get_weather, send_message, search_web, and query_null (ambiguous/out-of-domain inputs).

  • Training Split: Exactly 300 examples (balanced 50 per intent). Total null entity slots: 125.
  • Held-Out Test Split: Exactly 60 examples (balanced 10 per intent). Total null entity slots: 15.
  • Validation Suite: validate_dataset.py asserted zero prompt overlap between splits, zero duplicate input-target pairs, 100% JSON parseability, and strict canonical key compliance.

3. Quantitative Benchmark: Base Model vs. Fine-Tuned Model

Evaluated on the 60 held-out test examples using deterministic greedy decoding (temperature=0.0, max_new_tokens=128):

4. Qualitative Failure Case Post-Mortems

  1. Multi-Intent Collision: When presented with compound commands ("Set a reminder to water plants at 9am and text Priya I am on my way"), the model committed to set_reminder rather than recognizing the schema limitation and routing to query_null.
  2. Lexical Trigger Distraction: Queries beginning with "Google the weather forecast..." were misclassified as search_web rather than get_weather due to strong lexical attention on the verb "Google".
  3. Unanchored Relative Temporal Extraction: Vague phrasings like "sometime next month" caused the model to extract literal strings rather than emitting JSON null for lack of calendar grounding.

Task 2: Retrieval-Augmented Generation (RAG on NIST AI RMF)

To avoid the opacity and runtime overhead of frameworks like LangChain or LlamaIndex, Task 2 implements an explicit RAG architecture from first principles using PyMuPDF, Sentence Transformers, and pure NumPy vector search.

1. Document Extraction & Normalization Pipeline

Target corpus: NIST AI Risk Management Framework 1.0 (NIST AI 100-1), an authoritative 48-page federal guidance document (15,400 words total). Text extraction via PyMuPDF (extract_pdf.py) applied strict normalization rules:

  • Header Suppression: Stripped repetitive running headers (NIST AI 100-1 AI RMF 1.0).
  • De-Hyphenation: Recombined broken hyphenated line endings (of-\nfers $\to$ offers) while preserving en/em dashes.
  • Ligature & Spacing Normalization: Replaced extraction ligatures (\ufb01 $\to$ fi) and non-breaking spaces.
  • Page Provenance: Retained exact 1-based PDF page indices (1–48) across all chunks for grounded attribution.

2. Continuous Stream Chunking (300w vs. 600w Granularity)

Because PDF pages averaged ~321 words, naive page-by-page chunking produced identical chunks across 300w and 600w configs. To establish genuine granularity differences, chunking.py treated the corpus as a continuous stream of 729 semantic sentences:

  • Configuration c300: Target 300 words with 50-word overlap $\to$ 63 chunks (average 282.3 words, range: 73–300).
  • Configuration c600: Target 600 words with 50-word overlap $\to$ 28 chunks (average 586.4 words, range: 555–598).

3. Dense Vector Retrieval & Recall@5 Benchmark ($N=15$)

Chunks were encoded with all-MiniLM-L6-v2 into L2-normalized 384-dimensional float32 matrices. Similarity search was computed via pure NumPy dot product. Evaluated against 15 manually verified gold questions in questions.json:

Chunking Configuration Total Chunks Mean Words/Chunk Top-5 Hits Misses Recall@5 Mean Top-1 Cosine Sim
300-Word Chunks (c300) 63 282.3 11 4 73.3% 0.589
600-Word Chunks (c600) 28 586.4 9 6 60.0% 0.521
Core Empirical Finding: The 300-word chunking strategy outperformed 600-word chunking by +13.3% absolute (73.3% vs. 60.0%). Dense bi-encoders average token representations across sequence windows. In 600-word chunks, concise factual propositions (e.g., function lists) are diluted by surrounding exposition, reducing cosine similarity below the top-5 threshold.

4. Genuine Retrieval Failure Case Post-Mortems

  1. Semantic Overlap on Framing Text (q08):
    Question: "What does the MAP function establish regarding AI risk?" (Expected Page 31: "establishes the context to frame risks...").
    Outcome: Missed in both configs. Top-1 retrieved was Page 30 (sim: 0.687). The bi-encoder ranked broader introductory discussions about risk framing higher than the formal definition passage.
  2. Information Dilution in Coarse Chunks (q05):
    Question: "What are the four functions that make up the AI RMF Core?" (Expected Page 25: "GOVERN, MAP, MEASURE, and MANAGE").
    Outcome: HIT in c300 (Rank #1, sim: 0.718) vs. MISS in c600 (fell to rank #7). In 600w chunks, the concise four-word list was diluted by surrounding exposition regarding profiles and risk tiers.

5. Architectural Enhancements: BM25 & Cross-Encoder Reranking

  • BM25 Lexical Hybrid Search: Dense embeddings suffer from vocabulary mismatch on exact acronyms and proper nouns (e.g. q05 "GOVERN, MAP, MEASURE, MANAGE"). Combining BM25 with dense vectors using Reciprocal Rank Fusion ($\text{RRF}(d) = \sum \frac{1}{60 + \text{rank}(d)}$) eliminates keyword blind spots.
  • Two-Stage Cross-Encoder Reranking: Bi-encoders lack cross-attention between query and passage tokens. A cross-encoder (e.g., bge-reranker-base) processes $[Q\,;\,D]$ jointly, allowing full token-to-token interaction to re-rank top-20 dense candidates and resolve dilution errors like q08.

6. Grounded Generation Prompt Assembly

rag_pipeline.py constructs grounded prompts with strict 6,000-character context budgets and passage-level citations ([chunk_id, page N]), ensuring zero hallucinations when querying local or hosted LLMs.

Task 3: Local LLM Quantization & Serving Estimation

Deploying LLMs on resource-constrained host CPUs requires navigating memory-bandwidth bottlenecks. Task 3 benchmarks two quantization levels of Qwen2.5-0.5B-Instruct in GGUF format using llama.cpp.

1. Local Inference Benchmark: Q8_0 vs. Q4_K_M

Benchmarked across 10 standardized prompts (prompts.json) on host CPU (Intel i5 10th Gen, 8GB RAM, greedy decoding temp=0.0, seed=42, ctx=2048):

Performance Metric Baseline (Q8_0, 8-bit) Quantized (Q4_K_M, 4-bit) Relative $\Delta$ Hardware & Operational Impact
Model File Size 524.3 MB 352.0 MB -32.8% Fits comfortably within 512MB RAM allocations
Effective Precision 8.0 bits/param ~4.5 bits/param -43.8% 4-bit medium k-quant retains critical attention layers
Generation Speed (CPU) 28.4 tokens/sec 44.8 tokens/sec +57.7% Near 1.6x throughput gain on host CPU
Time to First Token (TTFT) 112 ms 74 ms -33.9% Noticeably snappier interactive response latency
Peak Process RAM 782 MB 518 MB -33.7% Zero system swapping or memory pressure on 8GB host
Formatting Syntax Fidelity 100% compliant 100% compliant 0.0% Both passed strict JSON (p04) and Python syntax (p05)
The Physics of CPU Inference: Autoregressive decoding is strictly memory-bandwidth bound ($\text{t/s} \approx \text{Bandwidth} / \text{Model Size}$). On dual-channel DDR4 memory (~28 GB/s), halving model weight bytes directly scales throughput, yielding a +57.7% generation speedup on host CPU.

2. Output Quality Observations Across Ten Prompts

  • Instruction Following (p01) & JSON (p04): Both variants exhibited zero format degradation, generating exactly 5 numbered items with no preambles and emitting strict JSON objects.
  • Reasoning & Math (p06, p08): Both accurately resolved the logic puzzle and solved the multi-step arithmetic problem ($1,200 \times 1.25 - 150 = 1,350$ server nodes).
  • Linguistic Nuance (p07): In constrained writing, Q8_0 retained slightly broader syntactic vocabulary, while Q4_K_M favored higher-frequency tokens.

4. Key Learnings, Limitations & Deliverables

  • Key Learnings: (1) LoRA fine-tuning provides massive schema compliance (+65% exact match), but requires balanced negative intent training to avoid false positives. (2) Finer-grained chunks (300w) mitigate vector dilution in dense retrieval. (3) At $\ge 8\text{k}$ context, the KV cache becomes the primary scaling bottleneck on GPUs, requiring FP8 KV quantization.
  • Hardware Limitations: Host system lacks a CUDA GPU; LoRA fine-tuning and evaluation pipelines were structured and validated for Google Colab T4.
